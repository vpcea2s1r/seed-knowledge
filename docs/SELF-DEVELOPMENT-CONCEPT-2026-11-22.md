# Концепция саморазвития проекта (22.11.2026)

**Запрос оператора:** «исследуй концепцию саморазвития в проекте». Источники: локальные протоколы (`SELF-LEARNING`, `SELF-IMPROVEMENT`, `AUDIT-PROTOCOL`, `LESSONS-INBOX`, скилл `session-retro`), наша практика этой сессии, внешние исследования 2025–2026. Только анализ; конфигурация и прод не менялись.

## 1. Что мы называем саморазвитием (определение)

**Саморазвитие ≠ обучение модели.** Мы не меняем веса и не «становимся умнее сами». Развитие — это улучшение **контура вокруг модели**: инструменты, скиллы, память, eval'ы, чекпоинты и проверка фактами.

> Улучшение считается состоявшимся только если замерено: **меньше повторов известных ошибок** и **быстрее/дешевле правильный контекст**. «Стало лучше на глаз» не принимается (AGENTS.md, N9 ТЗ SEED).

Оси эволюции (по обзору self-evolving agents, arXiv:2507.21046): **what** evolving (model / memory / tools / architecture), **when** (intra- vs inter-task), **how** (feedback, textual reflection, search). Мы эволюционируем **memory + tools + skills**, на межзадачном уровне, через текстовую рефлексию и проверку.

## 3. Что внешние исследования говорят про риски «саморазвития»

| Исследование | Факт | Что это значит для нас |
|---|---|---|
| **How Feedback-Free Self-Evolution Reshapes Agent Skills** (arXiv:2611.25534, 19.11.2026) | Модели, переписывающие экспертные скиллы **без обратной связи**, ухудшают их: −15 п.п. на SkillsBench за 30 раундов; теряется знание вне prior модели. Маркировка такого знания (SkillDiff) даёт +4,8 п.п. **без изменения текста** | **Не разрешать авто-переписывание скиллов.** Нужно помечать «экспертное знание, которое модель не придумает сама» и запретить его стирать |
| **Beneath the Surface / RSIHub** (arXiv:2611.07624, 05.11.2026) | Эволюция харнесса **перераспределяет** успех: все 16 агентów получили новые задачи и потеряли старые; лучший по баллу не дал лучшего прироста; нужен preservation-aware eval | Любая правка скилла — **кандидат на регрессию**: нужен набор регрессионных задач «до/после», а не только новый балл |
| **SEA-Eval** (arXiv:2604.08988) | Success rate создаёт «иллюзию способности»: при одинаковом SR расход токенов отличается до 31,2×; настоящая эволюция = монотонное снижение токенов при повторах; есть pseudo-evolution | Наш `time_to_answer_sec` — правильная метрика, но нужно смотреть **тренд по повторам**, а не один замер |
| **CDSE** (arXiv:2610.23599) | Эффективнее держать знание по функциональным ролям: Meta / Experience / Tool / Script; кросс-модельный трансфер +4,2 п.п., кросс-харнесс +3,3–3,4 п.п. | Наш T2K-журнал пока плоский; стоит добавить роли (у нас есть `kind`, но нет `Meta/Tool/Script`) |
| **A Survey of Skill Evaluation and Evolution** (ACL 2026, arXiv:2606.11435) | 4 paradigмы: execution feedback, trajectory distillation, compression, RL; не хватает продольной оценки и метрик сжатия | Наш цикл — это execution feedback + ручная дистилляция; не хватает продольной таблицы |
| **CoEvoSkills** (arXiv:2604.01687) | Само-эволюционировавшие скиллы переносятся на другие модели: +35–44 п.п. | Переносимый SEED-источник имеет смысл: опыт не привязан к одной модели |

## 5. План развития (по приоритету)

### P0 — прямо сейчас (без сети)
1. **Правило сохранения:** скилл нельзя переписать только потому, что «так логичнее». Изменение допускается при наличии evidence (команда/лог/замер) и только с пометкой `verified`. Экспертные знания помечать как `expert-only` (аналог SkillDiff) и не удалять при дистилляции.
2. Добавить в SEED концепцию **C-13 «Саморазвитие»** с каноном в этом документе и `seed concepts "саморазвитие"`.
3. Проводить `session-retro` после каждой значимой задачи (сейчас вызывается вручную) — метрика повторности цифрой.

### P1 — eval-контур (по команде)
4. Набор из 5–7 репрезентативных задач 1С (замер версии, загрузка .cfe, extensions check, IBCheckAndRepair, CheckModules, bootstrap, concepts) с ожидаемым результатом — **baseline до правки и после**.
5. Хранить тренд `time_to_answer_sec` по повторам; тревога при росте (pseudo-evolution по SEA-Eval).
6. Авто-захват хуками agentmemory (сейчас ручной `feedback`) + `AGENTMEMORY_INJECT_CONTEXT` для старта сессии.

### P2 — зрелость
7. Гейт: кандидат на изменение скилла проходит eval → human approve → git; при регрессе — `supersedes`, не удаление.
8. Роли CDSE в T2K-журнале (Meta/Experience/Tool/Script) и кросс-модельная проверка переноса.
9. A2A-делегирование + общий daemon team feed (см. `MESH-INTEGRATION-RESEARCH-2026-11-22.md`).

## 6. Честные ограничения

- Мы **не меняем веса модели**; «умнее» означает только meilleur контур и меньше повторов.
- Автономное обучение **не даёт права трогать прод** — все мутации по команде оператора.
- Без eval-набора любая «оптимизация» скилла может быть **регрессией**, которую мы не заметим (RSIHub).
- Внешние исследования — бенчмарки, не гарантия нашего результата; цифры (+4,8 п.п., −15 п.п.) заимствованы как ориентиры, не как наши замеры.
