## [БЛОКИРОВКА] Закрыть сеансы и регламентные задания перед обновлением   #обновление #сеансы
Дата: 2026-11-21
Проблема: обновление 2.1.27.1 → 2.1.38.11 на клиент-серверной базе; пользователи не должны зайти во время реструктуризации.
Решение: COM-коннектор 32-bit (`C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe`), подключение к **рабочему процессу :1561** (не :1541 — «Сервер недоступен»):
```
$com=New-Object -ComObject V83.COMConnector
$cwp=$com.ConnectWorkingProcess('tcp://[internal-host]:1561')
$cwp.AddAuthentication($user,$pwd)
$ib=$cwp.GetInfoBases() | где Name -eq 'DocumentSy'

```
Разблокировка — те же поля в `$false`, `PermissionCode=''`. Для служебных CLI-команд передавать `/UC"GodMode = On"`.
Доказательство: перечитывание свойств дало `SessionsDenied=True ScheduledJobsDenied=True`, после обновления `False/False`. Простой пользователей ~26 мин (19:46→21:12).
Ловушки: `Updater1C -BlockSessions` standalone **зависает** — ключ работает только с `-Execute`, а `-Execute` — только PROF-версия (отчёт «проблемы с лицензией»). Админ кластера НЕ нужен: `ConnectAgent` + `Authenticate` в кластере требует прав, а `ConnectWorkingProcess :1561` — нет.

## [ПРАВА] Почему пользователи читают все документы                #права #доступ
Дата: 2026-11-22
Проблема: «права на чтение у всех, кто-то читает документы, которые ему не положено».
Решение (по документации глава 26 ИТС и разбору doc-lvv): в ДГУ 2.1 механизм — **Полномочия** (бывшие «Профили групп доступа») + **Политики доступа** + **Рабочие группы** объектов + права на папки. Включить флаг **«Использовать ограничение прав доступа»**, затем обновить права; в клиент-серверном варианте включить **«Отложенное обновление прав доступа»**.
Замер из живой базы: `get_access_rights('Документ.ВходящееПисьмо', ['Чтение'])` → роли **ПолныеПрава** и **РаботаСоВстроеннойЭлектроннойПочтой**. Если «Полные права» назначены широкому кругу — отсюда и чтение всего.
Важно: если у документа заполнена **рабочая группа**, политики и права папок **перестают действовать** — доступ только по ней. Права по папкам дополнительно сужают доступ. «Права users на объект есть, если есть хотя бы одно разрешение и нет ни одного запрещения».
Проверка (рекомендация 1С): создать в защищённой папке файл с контрольным словом, обновить индекс поиска, войти под проверяемым пользователем, сделать полнотекстовый поиск — должен вернуть 0.
Ловушки: документация ИТС (`its.1c.ru`) отдаёт paywall/кракозябры через webfetch и 401 на прямой src; читать через браузер (авторизован) или пользоваться проверенными статьями.
Ссылки: `https://www.doc-lvv.ru/knowledge/prava-dostupa-v-1s-dokumentooborot-21`, `https://its.1c.ru/db/doccorp21/content/791/hdoc`, `%TEMP%\opencode\its-ctx.txt`.

## [АУДИТ] Где реально видно «кто что смотрел» — регистр ОбращенияКОбъектам   #аудит #просмотры
Дата: 2026-11-22
Проблема: «посмотри, где рылась Мишарина/что читают задачи Никитина». Журнал регистрации такие события не пишет.
Решение: **`РегистрСведений.ОбращенияКОбъектам`** — в ДГУ он хранит факт обращения: `Объект` (ссылка), `Пользователь` (ссылка), `ДатаПоследнегоОбращения`. Это и есть следы просмотров. Запрос:
```
ВЫБРАТЬ ПРЕДСТАВЛЕНИЕ(Обращения.Объект) КАК Объект,
  ПРЕДСТАВЛЕНИЕ(Обращения.Пользователь) КАК Пользователь,
  Обращения.ДатаПоследнегоОбращения КАК Дата
ИЗ РегистрСведений.ОбращенияКОбъектам КАК Обращения
ГДЕ Обращения.ДатаПоследнегоОбращения МЕЖДУ &d1 И &d2
УПОРЯДОЧИТЬ ПО Обращения.ДатаПоследнегоОбращения УБЫВ
```
Важно: лимит 1000 строк обрезает выборку — дробить на недели/дни и обязательно `УПОРЯДОЧИТЬ ПО ... УБЫВ`, иначе приходят только ранние даты. Поле «Пользователь» в ответе — уже имя (не UUID), фильтр `user` в `get_event_log` тоже работает по полному имени (не по UUID, не по «Мишарина» — только «Мишарина Наталья Валерьевна»).
Замер (ноябрь 2026):
- Горохова: 20 обращений 3 и 6.11 (вх 3564/3566/3525–3527, задачи Минобрнауки по молодёжной тематике).
- Мишарина: 183 обращения, все 17–19.11 (пик 144 — 18.11), 2–6.11 — ноль.
- Читатели объектов с упоминанием «Никитин»: 166 — из них сам Никитин 150, Никитина И.С. 9, остальные по 1–2 (Голубева, Паскаль, Лаврова, Соловьёва, Мишарина — все один рапорт 3733). Чужой почты никто не читает массово.
Ловушки: `LIKE &param` по `ПРЕДСТАВЛЕНИЕ(Ссылка)` в языке запросов 1С **не работает** («Неверные параметры ПОДОБНО»); параметр-ссылка `Ссылка = &ref` тоже не проходит — выгружать Range и фильтровать по тексту. Регулярки с `/…/i` по кириллице в Execute Workspace вели себя странно — надёжнее `String.includes('Никитин')`.
Ссылки: запрос выше, `get_event_log` из `1c-toolkit`, `docs/KB-1C.md`.

## [ПРАВА] Запрет чтения ЧУЖИХ задач — политиками НЕ решается        #права #задачи #важно
Дата: 2026-11-22
Проблема: «Мишарина открыла задачу Никитина — как запретить чтение чужих задач политиками доступа?»
Решение (по официальной справке, проверено — НЕ гадать):
- **Права на задачи и процессы в ДГУ 2.1 НЕ настраиваются вручную.** Дословно: «Права на задачи и процессы не настраиваются, а вычисляются программой автоматически. Права на просмотр задачи и процесса имеют все участники данного процесса, а также их руководители (в том числе и с учетом переадресации)».
- Следовательно **политики доступа НЕ могут запретить чтение чужих задач** — их разрезы это организации, грифы, виды документов, группы доступа контрагентов/физлиц; задач там нет.
- Что реально работает:
  1. **Рабочая группа документа** — если заполнена, доступ только по ней и политики перестают действовать. Это главный рычаг «чтобы не читали лишнего».
  2. **Права на папки** — дополнительно сужают доступ (внутренние документы, файлы, письма, мероприятия, проекты, форум). Правило: «права есть, если есть хотя бы одно разрешение и нет ни одного запрещения».
  3. **Политики доступа** — для документов/НСИ (виды, грифы, организации), не для задач.
  4. Роль **«Контроль задач и процессов»** и **«Руководитель подразделения»** дают расширенный доступ к задачам — не назначать без нужды.
- Проверка факта (замер 17.11, задача `a32f30ba…` «О рапорте Никитину Ю.А., вх 3733»): Автор=Малынова Е.С., Исполнитель/Текущий=Никитин Ю.А., Мишарина не указана ни в одном поле — но открыла карточку 17.11 14:30. Это штатный доступ «все участники процесса + руководители», не чтение почты.
Ловушки: не обещать запрет через политики — это противоречит справке. Если нужно реально закрыть — заполнять рабочие группы документов и убирать широкие полномочия, плюс аудит через `ОбращенияКОбъектам`.
Ссылки: `https://www.doc-lvv.ru/knowledge/prava-dostupa-v-1s-dokumentooborot-21` (глава 26), `get_access_rights`, `get_metadata('Задача.ЗадачаИсполнителя')`.
